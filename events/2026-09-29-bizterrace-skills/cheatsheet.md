# Skills入門 — 公開Skill「HTML Visualizer」再現チートシート

対象: 普段AIを使っているビジネス職・企画職・AI推進担当 / 所要: 借りる 10〜15 分、作って自動で呼ぶまで 30 分 / 最終確認: 2026-09-29（リンク・当日の版の中身・置き場所を開催当日に確認）

> **教科書**（4段階を、チャットAI と Claude Code・Codex それぞれの手順で）: https://biz-terrace-ai.pages.dev/handson/2026-09-29/textbook.html
>
> 基礎（Skill とは）と、借りる・直す・作るの3つの演習を1ページにまとめた HTML 版もあります。【】を埋めれば自分の仕事にも使え、型は GitHub を開かずにボタンでコピー・保存できます: https://biz-terrace-ai.pages.dev/handson/2026-09-29/guide.html

当日のワークは、公開されている型を普段のAIにリンクで渡して1回動かします（**借りる**。この「1」を見ながら進められます）。持ち帰ってからは、型を自分のやり方に**直し**、自分で**作り**、AIが**自動で呼び出す**ところまで、このまま進められます。AIが出した結果の確認と、その利用の判断は試す人が持ちます。

| 段階 | やること | 型の渡し方 |
|---|---|---|
| 1. 借りる（当日） | 公開の型を1回動かす | 会話のたびに渡す（リンク・添付・貼り付け） |
| 2. 直す | 判断基準を1か所だけ自社のやり方へ | 同上 |
| 3. 作る（合う型がなければ） | いつもの仕事の直後に「今のをSkillにして」 | 同上 |
| 4. 自動で呼び出す | 型を環境に登録する | **渡さない。** AIが仕事に合う型を自分で選んで開く |

## 前提

- 道具: **普段お使いのAIで構いません**（ChatGPT / Microsoft Copilot / Gemini / Claude / Codex / Claude Code 等）。1〜3に新しいアカウントや環境構築は不要です
- 型: 公開OSS `yamamonlab/html-visualizer`（https://github.com/yamamonlab/html-visualizer）。リンクは常に最新版を指します。当日に使った版はタグ `bizterrace-2026-09-29` で残しています
- データ: **公開資料かダミーデータだけ**を使ってください。業務データ、顧客情報、個人情報は入れない。業務の資料を入れるのは、**会社で利用が許可されたAIだけ**です
- このSkillの用途: **自分が受け取った長文を理解するための道具**です。提出物・配布物を作る型ではありません

## 1. 借りる — 当日のワークを再現する

AIに渡すのは **型・資料・依頼文** の3つです。型はリンク1本で渡せます。

### いちばん短い渡し方（リンクを読めるAI）

下の3行をそのまま貼ります。

```text
https://github.com/yamamonlab/html-visualizer
このSkillを使って、次の資料を完全版のHTMLにしてください。
https://raw.githubusercontent.com/yamamonlab/html-visualizer/main/examples/sample-document.md
```

- 1行目が型です。リンク先の案内に、AIが読むファイル（`SKILL.md` と `references/` の2つ）が書いてあります。**SKILL.md だけを渡した状態は完全な実行ではありません。**
- 3行目が資料（社内AIツール導入検討の架空メモ）です。自分の資料で試すときは、ファイルを添付し、「次の資料」を「添付の資料」にします。
- 「完全版」を入れると、AIが途中で省いた簡略版を出しにくくなります。

フォルダを扱えるAI（Codex / Claude Code）には、作業フォルダで次を送ります。

```text
https://github.com/yamamonlab/html-visualizer
このSkillを使って、examples/sample-document.md を完全版のHTMLにしてください。HTMLファイルで保存してください。
```

### リンクで読めないとき

| 起きたこと | 渡し方 |
|---|---|
| 外部リンクの取得が止められている | [手順ガイド](https://biz-terrace-ai.pages.dev/handson/2026-09-29/guide.html#lab1)のボタンで、型の本文をまとめてコピーして貼るか、1つのファイルに保存して添付する（約4万字。Copilot は拡張子を `.txt` に変えて添付） |
| GitHub ごと止められている | 別の端末で本文をコピーする。難しければ、下の完成形で結果だけ確かめ、後で自分の環境でやり直す |

### 確認ポイント

正解のレイアウトを当てるものではありません。次が満たされているかを見ます。

- 先頭の見出しとリードだけで「何の資料で、今どういう状態か」が分かる
- 最初の画面に、分かっていること / まだ分かっていないこと / これから、の一覧が並ぶ（未確認のことが「分かっていること」に入っていない）
- 数値が原文の表記のまま（合計・差・単位の書き換えをしていない）
- 比較・推移・因果は表や図に、それ以外は読みやすい本文になっている
- 推測・未確認が事実と混ざっておらず、誰の発言かが残っている
- **原文にない優先順位・推奨・担当・日付が足されていない**（既定は理解支援のみ。判断材料が欲しい時だけ「比較して判断材料をください」と追加で頼む）
- 末尾の「原文との対応」を開くと、画面の内容を原文の一節へ辿れる

モデルによって文章や配置の細部は変わります。狙いは完全一致ではなく、同じ判断基準と骨格へ寄せることです。

完成形の例: https://biz-terrace-ai.pages.dev/handson/2026-09-29/cognitive-view.html

### つまずきどころ

| 症状 | 原因 | 対処 |
|---|---|---|
| 普通の要約文が返る | 型が読めていない | `SKILL.md` だけでなく `references/` まで読んだか、AIに聞いて確かめる。読めていなければ本文の貼り付けかファイルの添付へ |
| AIが「読めません」と言う | 外部取得が止まっている | 「リンクで読めないとき」の表のとおり、本文の貼り付けかファイルの添付へ |
| HTMLがコードのまま表示される | プレビュー表示になっていない | チャット内のプレビュー（アーティファクト・キャンバス）表示へ切り替える。難しければ上の完成形URLを開く |
| 無料枠の上限で止まる | メッセージ制限 | 上の完成形URLで結果を確認し、後で自分の環境でやり直す |

Copilot がリンクを読めるかは、会社の管理者設定によって変わります。読めなければ、型のファイルの拡張子を `.txt` に変えて添付するのが確実です（約4万字を貼ると入力上限に当たりやすい）。

## 2. 直す — 判断基準を1か所だけ書き換える

借りた型は、そのままでは自社のやり方と少し違うことがあります。当日の実演では、冒頭の一覧の列「分かっていること / まだ分かっていないこと / これから」を、自社の会議の決まり「結論 / 影響 / 次に決める論点」に書き換えました。同じ資料・同じ依頼でも、最初に見えるものが変わります。情報は消しません。

- **その回だけ効かせる**: 依頼文の後ろに1行足す

  ```text
  ただし、冒頭の状況の一覧は、次のようにしてください。列を「結論 / 影響 / 次に決める論点」の3つにする。この順で。原文にない論点は書かない。
  ```

- **毎回効かせる**: 型をファイルで保存し（ガイドの「型を1つのファイルで保存」か、4-1のまとめて取る方法）、該当の行を書き換えてから渡す。4で登録したなら、登録した `SKILL.md` を直す

1回に1か所だけ変えて、書き換える前と比べます。何か所も同時に変えると、どの変更が効いたのか分からなくなります。

## 3. 作る — いつもの仕事の直後に型にしてもらう

白紙から書き始めません。自分の仕事で「毎回同じ形で頼んでいること」を1つ選び、いつも通りAIとやり取りし、注文をつけて直してもらいます（「宿題は表にして」など）。うまくいったら、**同じ会話のまま**次を送ります。

```text
今やった一連の作業を、別の仕事でも同じ品質で再現できるように、手順・判断基準・出力形式をまとめたSkill（SKILL.md）にしてください。今回の具体的な社名や数値などの固有名詞は除外し、どの業務でも使える一般的な手順にしてください。先頭は --- の行で挟み、その間に name（英小文字とハイフンの名前）と description（いつ使うか・使わないかの説明）を書いてください。本文は「やってはいけないこと」「進める順番」の見出しで書いてください。
```

出てきた型から引き算します。

- **消す**: 丁寧に書く／分かりやすく／正確に、のような、どのAIも元からやること
- **残す**: 宿題には必ず担当と期限を書く／分からないところは「記載なし」、のような、自分の職場の決まりと出力の形

作った型は、同じ資料を型なしと型ありで1回ずつ頼んで比べ、足りないところだけを書き足します。4へ進まない場合は、テキストとして保存し（OneNote、Teams のピン留め、社内の共有フォルダなど）、次の会話の1通目に貼って使います。

## 4. 自動で呼び出す — 型を環境に登録する（本来の使い方）

1〜3では、型を会話のたびに人が渡しました。Skills に対応した環境へ型を**登録**すると、AIはまず各型の `name` と `description` だけを読み、仕事に合う型のときだけ本文と `references/` を開きます。依頼文で型の名前を言う必要も、毎回貼る必要もなくなります。型をいくつ登録しても、最初に読むのは先頭の数行だけです。

### 4-1. 型をフォルダにする

登録する単位は**フォルダ**です。フォルダ名は `name` と同じにします。

```text
meeting-minutes/          ← name と同じ名前
  SKILL.md                ← 先頭に name と description、本文に手順
  references/             ← 長い参考情報があれば（なくてもよい）
```

- 借りた型: 最新版をまとめて取り、フォルダごと使う（`SKILL.md` だけを取り出さない）

  ```text
  https://github.com/yamamonlab/html-visualizer/archive/refs/heads/main.zip
  ```

  ダウンロードした ZIP をダブルクリックして展開します（ブラウザによっては自動で展開されます）。`html-visualizer-main` というフォルダができるので、名前を `html-visualizer`（`name` と同じ）に変えます。Mac のターミナルを使うなら、4-3 の1行で取得と配置が一度に済みます

- 作った型: 3で出てきた本文を `SKILL.md` という名前で保存し、`name` と同じ名前のフォルダに入れる

### 4-2. 自動で選ばれる説明（description）を書く

AIが型を選ぶ手がかりは、主に `description` です。**いつ使うか**を、実際の仕事の動作と資料の種類で書き、**使わないとき**も1つ書きます。

```text
---
name: meeting-minutes
description: 会議メモ・議事録の下書きを「決まったこと / 宿題（誰が・いつまでに） / 次回までに確かめること」の3つに分ける。雑談の要約や、議事録以外の資料には使わない。
---
```

「文章をきれいにする」のような広い言葉だけだと、関係ない仕事でも選ばれたり、逆に選ばれなかったりします。

### 4-3. 環境に置く

| 環境 | 置き場所（`~` はホームフォルダ。Mac は `/Users/<名前>`、Windows は `C:\Users\<名前>`） | 名前で呼ぶとき |
|---|---|---|
| Claude Code | 自分用: `~/.claude/skills/<name>/`　このプロジェクトだけ: `.claude/skills/<name>/` | `/<name>` |
| Codex | 自分用: `~/.agents/skills/<name>/`　このリポジトリだけ: `.agents/skills/<name>/` | `$<name>` か `/skills` |
| Claude アプリ（Skills を使えるプランで、コード実行をオン） | 型のフォルダ1つだけを ZIP に圧縮し（ZIP を開くと `<name>/SKILL.md` が見える形）、設定の Skills の画面からアップロードしてオンにする。4-1でダウンロードした ZIP はそのままでは使えない。展開して名前を `html-visualizer` に変えたフォルダを圧縮し直す | — |
| ChatGPT（Business・Enterprise など） | Skills の機能から登録 | `@<name>` |
| 対応していない・使えないとき | GPT・プロジェクト（ChatGPT）、Gem（Gemini）、エージェント（Microsoft 365 Copilot。指示は8,000字まで、知識ファイルは `.md` を `.txt` に）、プロジェクト（Claude）の指示に本文を入れる。その中の会話ではいつも使われる | — |

Mac のターミナルで、HTML Visualizer を Claude Code の自分用に置く例（Codex なら `~/.claude/skills` を `~/.agents/skills` に替える）:

```bash
git clone https://github.com/yamamonlab/html-visualizer ~/.claude/skills/html-visualizer
```

最新版にするときは `git -C ~/.claude/skills/html-visualizer pull` です。ZIP から展開した `html-visualizer` フォルダを、ファインダーやエクスプローラーでコピーしても同じです。`.claude` や `.agents` は隠しフォルダなので、Mac のファインダーでは「移動 → フォルダへ移動」に `~/.claude/skills` と入れて開きます（`Cmd+Shift+.` で隠しフォルダを表示することもできます）。置いた型が出てこなければ、Claude Code は `/reload-skills`、Codex は再起動します。

### 4-4. 自動で選ばれるか確かめる

新しい会話で、**型の名前を言わずに**、説明に合う仕事を頼みます。HTML Visualizer を登録した場合は、1のサンプル資料を渡して次を送ります（自分で作った型なら、いつもの頼み方で）。

```text
この資料を、短時間で全体像をつかめる形にしてください。
```

型の「進める順番」のとおりの形で返れば、自動で選ばれています。続けて、説明の「使わない」に当たる仕事も頼み、その型が使われないことを確かめます。選ばれなければ `description` を実際の頼み方に近い言葉へ直し、関係ない仕事で選ばれるなら「使わない」を足します。説明が似た型を2つ登録すると、どちらが選ばれるかがぶれます。似てしまったら、それぞれの `description` に相手の仕事を「使わない」として書きます。

### 4-5. 登録するときの約束

- 借りる型は出所を確かめ、中身を読んでから登録する。HTML Visualizer のように確認用のプログラム（`scripts/`）を同梱した型は、プログラムを動かせる環境（Codex・Claude Code・コード実行が有効な Claude アプリなど）では実行されることがあるので、社内のルールに沿って確認してから使う
- 同じ名前の型がすでにあるときは上書きしない。どちらを使い続けるかを先に決める
- 社内で配るときは、何人かで見せ合ってレビューしてから「公認の型」にする。ときどき見直して、要らなくなったルールを引き算する

## 明日から始める

| 方法 | こんな環境なら | やること |
|---|---|---|
| **A. リンクで渡す** | AIが公開Webを読める | 1の「型を渡す」のとおりリンクを貼る |
| **B. ファイルで渡す** | 社内に共有された型がある / 外部リンクは止められている | 型のフォルダのファイル（`SKILL.md` と `references/`）を会話に添付する |
| **C. 本文を貼る** | ファイル添付も外部リンクも使えない | `SKILL.md` などの本文を会話の1通目に貼る。よく使うなら Teams のピン留めや OneNote に置いておく |
| **D. 自分で作らせる** | 手元に型がない / まず気軽に試したい | 3のとおり「今のをSkillにして」と頼む |

Skills に対応した環境（Claude Code・Codex・Claude アプリなど）を使えるなら、A〜D で手に入れた型を **4で登録**すると、次からは渡さずに済みます。

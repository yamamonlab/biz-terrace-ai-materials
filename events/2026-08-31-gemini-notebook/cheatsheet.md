# Gemini Notebookで学ぶ、調査から資料までをつなぐAI入門 — 再現チートシート

対象: 表形式データの集計・可視化・資料化をAIで試したい初心者 / 所要: 30〜45 分 / 最終確認: 2026-08-31（当日のライブデモ）

当日の「公開CSV → AIがPythonを生成・実行 → 集計表 → グラフ → 人の検算 → PDF」を、自分の環境で同じ順にたどる手順です。AIが出した結果の確認と、その利用の判断は試す人が持ちます。

## 前提

- 道具: Gemini Notebook（旧 NotebookLM）。コード実行とファイル生成が使えるアカウントであること。提供範囲はプラン・アカウント・Workspace設定で異なるので、最初に §1 で確かめる
- データ: **公開CSVか合成データだけ**を使う。業務データ、顧客情報、個人情報は入れない
- 用意するもの: 公開CSV 1つ（例: 政府・公的機関が公開している統計の年次テーブル。行数は数百〜数千行で十分）、その中で「答えが自分で確かめられる」チェック値を1つ（例: ある年の合計、ある国の値）

## 手順

### 1. 使える機能を確かめる

新しいノートブックを作り、CSVを追加せずに次を聞く。

```text
このノートブックで、アップロードしたCSVに対してPythonコードを生成・実行して集計やグラフ作成ができますか。できる場合、その手順を3行で教えてください。できない場合は、その旨だけ答えてください。
```

期待する結果: 「できる」と、実行までの流れが返る。「できない」なら、以降は閲覧用として読み、§7 の別環境で試す。

### 2. 実行前に、問いと期待結果を書き出す

ノートブックの外（メモ帳でよい）に、次の5つを先に書く。当日のデモも実行前にこれを共有した。

| 項目 | 例 |
|---|---|
| 使うCSV | `<ファイル名>`（公開元と取得日） |
| 確認したい問い | 直近5年で、地域別の合計はどう変化したか |
| 期待する集計軸 | 年 × 地域、単位は「人」 |
| チェック値 | 2024年の合計 = 公開元の表と一致すること |
| 最終成果物 | 集計表1枚とグラフ1枚をPDFにまとめる |

期待する結果: 「正解を確かめる手段」が実行前に決まっている。

### 3. CSVを読み込ませ、構造を確認させる

CSVをソースとして追加し、次を送る。

```text
追加したCSVについて、Pythonで読み込み、次を報告してください。
1. 行数と列数
2. 各列の名前と型、欠損の数
3. 単位や期間が分かる列があれば、その値の範囲
数値を要約する前に、まずこの構造確認だけを返してください。
```

期待する結果: 列名・型・欠損数が表で返る。ここで単位や期間の列を自分の目で確かめる。

### 4. 集計をさせる

```text
このCSVを使い、<年の列> と <地域の列> で <値の列> を合計した集計表を作ってください。
- Pythonで集計し、実行したコードと結果の表を両方見せてください
- 欠損値は除外し、除外した行数を報告してください
- 単位は <単位> のまま変えないでください
```

期待する結果: 生成コード、実行ログ、集計表の3つが返る。§2 のチェック値と一致するかをここで確認する。

### 5. グラフにさせる

```text
§4の集計表から、年を横軸、<値の列> の合計を縦軸にした折れ線グラフを作ってください。地域ごとに線を分け、凡例・軸ラベル・単位を必ず入れてください。
```

期待する結果: 軸ラベルと単位が入ったグラフ。凡例の地域名が集計表と一致することを確認する。

### 6. 検算して、直して、PDFにする

初回出力をそのまま使わず、次を送って差分を確認する。

```text
集計表について、次を確認して結果を報告してください。
1. 全期間・全地域の合計が、元CSVの <値の列> の合計（欠損除外後）と一致するか
2. 同じ年・地域の行が重複していないか
3. 最大値と最小値がどの年・地域か。異常に見える値があれば理由の候補を挙げてください
修正が必要なら、修正後の表を再掲してください。
```

確認が済んだら、成果物にまとめる。

```text
確認済みの集計表とグラフを、A4縦1枚のレポートにしてPDFとして出力してください。
先頭に「データの出典と取得日」「集計条件（期間・地域・単位・欠損の扱い）」を必ず記載してください。
```

期待する結果: 出典と集計条件が先頭に入ったPDF。

## 人が確認するところ

- [ ] 使ったCSVが公開データで、取得日と出典を書いたか
- [ ] 欠損・重複・単位の取り違えがないか（§3 と §6 の報告で確認）
- [ ] §2 で決めたチェック値と、集計表の値が一致するか
- [ ] グラフの軸ラベル・凡例・単位が集計表と一致するか
- [ ] PDFの先頭に出典と集計条件が入っているか
- [ ] 外部共有・意思決定に使う前に、もう一度元データに当たったか

## つまずきどころ

| 症状 | 原因の目安 | 対処 |
|---|---|---|
| コード実行の選択肢が出ない | アカウント種別・Workspace設定 | §1 の返答を確認。使えない場合は閲覧で型だけ持ち帰り、§7 で別環境を試す |
| 集計値がチェック値と合わない | 欠損の扱い、単位の混在、重複行 | §3 の構造確認に戻り、除外条件を明示して §4 をやり直す |
| グラフの線が多すぎて読めない | 地域の粒度が細かい | 上位5地域に絞るか、年の範囲を狭める指示を足す |
| 実行が長く止まる | 一時的な処理待ち | 90秒を目安に打ち切り、指示を短くして再実行する（当日も同じ基準で切り替えた） |
| PDFに出典が入らない | 指示に書いていない | §6 の2つ目の指示のように「先頭に必ず記載」と明示する |

## 7. 他の道具で同じことをする

Googleを使えない環境でも、「入力 → 実行 → 検算 → 成果物」の4工程は同じです。

- Microsoft 365 Copilot の Analyst エージェントなど、コード実行で表を分析できる道具に、§3〜§6 の指示をほぼそのまま渡せます
- 道具の優劣ではなく、「どこまでAIに任せ、どの数字と前提を人が確認するか」を先に決めることが、環境が変わっても効く部分です
